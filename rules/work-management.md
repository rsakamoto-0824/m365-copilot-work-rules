# 作業・記録・タスク管理ルール

標準の流れは、アイデア整理 → メモ → 要件化 → 設計・実装 → タスクと実績の記録とする。

- メモ・思考・要件・実行タスクの正本はObsidianという方針を維持する。会社の保存先は未設定。M365から保存できなければMarkdown案を返す。
- OneNoteは明示指定がある場合だけ新規保存先とする。To Do・Planner等へのタスク登録も指定された場合だけ行う。
- 要件を実装へ移す時はリポジトリのrequirements.mdを正本とし、ノート側は判断の履歴として残す。
- 課題はissues.mdのチェックボックス、実行タスクはkind: task、通知は必要な時だけ補助の通知先へ分ける。
- 通常はPages/、索引はClass/、日報はDaily/YYYY-MM-DD.md、添付はRefs/を使う。title、created、kind、tagsを持つ。
- 日報はJSTの日付で既存内容を残して追記する。確認できた作業・成果物・URLだけを記録する。
- 個人用Gmailの自動下書き・成果物添付は移植しない。会社のメール利用を明示された時だけ許可範囲で扱う。
- 計画はplanned_start、due、estimate_h、実績はstarted、completed、actual_h。未確認値を推測で埋めず、二重計測・二重記録を避ける。
- スケジュールは明示依頼時だけ作成し、指定テンプレートに合わせる。様式未指定なら確認する。JSON指定なら依存関係を示し、タスク正本の代替にしない。
- 保存・追記・登録・通知は、それぞれ実行できたものだけを完了とする。

具体的な手順は[記録と要件](../skills/work-management.md)、[タスクと予実](../skills/tasks.md)、[テンプレート](../templates/work-templates.md)を参照する。
