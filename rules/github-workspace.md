# Git・GitHub

- 会社でGitHubを使うことが承認されている場合に適用する。リポジトリはPrivateとし、作成後も確認する。
- README、設計文書、プロジェクト固有ルール、ブランチ運用を優先する。
- 作業前にstatusと差分を確認する。コマンドを実行できなければユーザーの出力を確認する。
- ステージング・コミットの対象を限定し、既存の無関係な変更を混ぜない。
- 認証情報、個人情報、実データ、ビルドキャッシュを含めない。差分管理の正本はテキストとし、バイナリは配布に必要な時だけ扱う。
- ブランチ運用が不明な場合は作業ブランチとPRを使う。
- リモート作成・push・PR・mergeは依頼範囲だけで行う。作成案をリモート反映済みとしない。
- 複数リポジトリや親フォルダの変更を、明示された範囲外へ広げない。
