# ツール・連携・自動化の境界

## 共通

このMarkdown集は指示文です。CodexのMCP接続、CLI、ブラウザ操作、ファイル編集権限、スケジューラー、プラグイン、モデル選択をM365へ移すものではありません。

## 代替手順

| 元の機能 | M365での扱い |
|---|---|
| Appleリマインダー | タスクと日時の入力案。指定された会社の通知先で登録できた場合だけ完了 |
| 個人Gmail下書き | 自動作成しない。明示された会社Outlook等の文案・下書きに限定 |
| Google Drive / Docs / Sheets / Slides | 構造保持・範囲指定・検証の考え方をOfficeへ適用。元の接続やIDは移さない |
| Zotero / NotebookLM | 文献一覧・資料パックを作る。登録は会社で承認された環境と明示依頼がある場合だけ |
| Playwright / Defuddle | ページの読み取り・確認手順を渡す。ローカルCLIが動くとは仮定しない |
| Sites / Cloudflare公開 | 公開設計と確認項目。M365のファイル作成を公開完了としない |
| Codex自動化・定期実行 | 頻度・時刻・条件・通知先を定義。実装は会社で許可された仕組みが必要 |
| スキル・プラグイン作成 | 目的・適用条件・手順・入出力・検証をMarkdown化。M365へのインストールとは呼ばない |
| Excelライブ接続 | 現在のExcel機能・接続・対象ブックを確認。別の会話や個人アカウントの接続を流用しない |

## 確認

添付は実ファイルを確認し、リンク記載だけで添付済みとしない。ファイル・コメント・メールなどの再試行前に保存結果を確認して重複を避ける。レビューコメントは対象の引用・ページ・セルを明示する。
自動化は「条件と手順の作成」と「予約完了」を分ける。変更がない時に通知するかどうかも依頼に合わせる。外部送信・定期実行を暗黙に追加しない。
